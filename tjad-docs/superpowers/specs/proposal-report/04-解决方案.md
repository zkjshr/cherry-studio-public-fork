# 第四章 解决方案

## 4.1 总体思路：以“能力即服务、知识即服务”为方法论主轴

本课题总体思路可概括为“一个主轴、一个应用、两类资产、一套机制”。我院智能化客户端“百事通”已确立“能力即服务、知识即服务”的产品架构方向：智能体运行时保持通用，场景应用通过“人设 × 能力 × 知识”的组合配置（preset）快速生成（出处：提案报告 §一 1.3）。灵感助手即在该成熟底座上完成的首个官方场景组合，而非从零开发的新应用。

落地层面遵循三条既定架构约束：其一，百事通桌面端（基于 Cherry Studio 企业化定制）零改动或极小改动，灵感助手对用户而言就是一个官方助手（出处：设计文档 §1；提案报告 §三 3.1）；其二，新增逻辑全部落在 gateway 服务网关——该网关已具备知识检索、企业用户鉴权、插件市场分发等模块，是课题新增能力的宿主（出处：提案报告 §三 3.1）；其三，WeKnora 知识引擎不改造，优秀项目库与地域文脉库仅为其新增的两个知识库（出处：提案报告 §三 3.1）。

机制层面，课题在 gateway 内落地三层注册机制——能力注册表（capabilities）、知识注册表（knowledge_sources）、场景组合表（presets），与既有企业库同范式；灵感助手本身即一份 preset，更换一份 preset 即派生另一场景。此机制是可复制性的直接保证，也是本课题区别于“做一个应用”的方法论价值所在（出处：设计文档 §4.1；提案报告 附表 D）。

## 4.2 灵感助手：面向设计前期工作流的伴随式应用

灵感助手以设计任务书为起点，形成六步闭环工作流（出处：设计文档 §3.1）：

1. **要素解析**（parse_brief）：解析任务书，生成结构化要素卡（功能、地点、规模、风格、约束），交用户确认；
2. **三路检索**（并行）：search_projects 检索内部优秀项目库相似项目；search_region 检索地域文脉库目标地档案；search_external 对未建库地区实时采集补充，生成轻档案并写回；
3. **灵感简报**（synthesize_brief）：融合三路素材生成结构化简报，内容全部注明来源；
4. **伴随式深化**：对话式追问、收窄、换向，会话状态显式维护“要素卡＋已采纳方向”，长对话不漂移；
5. **成果沉淀**（gen_concept_doc）：生成《项目构思文档》内部版，素材回链；
6. **提案升格**（upgrade_proposal）：内部构思成熟后升格为《前期策划提案》对外版，文风切换由人格层完成。

上述“大模型按需调用外部能力”的编排范式具有公开技术依据：ReAct 框架证明大模型交替执行推理与行动可显著提升任务表现与可解释性（来源：Yao 等，2022）；Toolformer 研究表明大模型可自主学习调用外部工具的时机与方式（来源：Schick 等，2023）；检索增强生成（RAG）则为“模型参数知识之外挂接可更新的外部知识源”提供了成熟范式（来源：Lewis 等，2020）。

灵感助手共规划 10 项能力端点（含后台建档 archive_project、地域采集 crawl_region、三期预留的 gen_image），均为 gateway HTTP 端点，输入输出由 JSON Schema 声明——Schema 即“能力即服务”的接口契约，亦是上架插件市场的清单（出处：设计文档 §3.2；提案报告 附表 B）。

## 4.3 输出三级阶梯

交付成果按能力成熟度分为三级，阶梯随能力上线自然涌现，并非写死的功能档位（出处：设计文档 §5）：

| 级别 | 内容 | 可用时点 |
|---|---|---|
| L1 检索原始结果 | 三路检索素材包，带引用未加工 | 一期 |
| L2 生成报告 | 灵感简报、构思文档，结构化有叙事线，素材全回链 | 一期 |
| L3 图文＋效果图 | 附实景/风貌图集与 AI 生成意向效果图（严格标注“AI 意向图”，与实景区分） | 二至三期 |

其中 L1 素材包为“结构化数据＋来源清单”的标准产物，一次实现三处复用：用户兜底结果、L2/L3 的输入、建档管道的中间件。

## 4.4 数据资产建设机制

**优秀项目库（内部独家资产）**：对 EKP 历年评优项目原始图档实施 LLM 半自动结构化建档——由大模型抽取草稿档案（设计要点、概念关键词、空间策略标签、图集归类、获奖信息），高置信自动入库，低置信进对话式人工审核队列；档案数据模型含 basic、design、culture、honor、media、source 六类字段，其中 source 保留 EKP 原始文档 ID，保证可溯源（出处：设计文档 §2.1；提案报告 附表 C）。

**地域文脉库（外部采集资产）**：采用双层结构——白名单重点地区（首批 10–20 个，覆盖长三角核心与业务重点城市）完整建库并季度自动重爬刷新；非白名单地区按项目需要实时采集生成轻档案，高频命中地区自动晋升白名单，晋升机制本身即为课题创新点（出处：设计文档 §2.2）。

**合规采集原则**：外部数据获取遵循“引用优于拷贝”——存储结构化摘要与来源链接，仅白名单地区存全文/图集；只采集公开内容，不触碰登录/付费墙内容；数据源按官方公开、百科知识、学术、UGC/生活、影像五类管理，每源一个采集适配器（adapter），声明覆盖范围、更新频率与合规级别（出处：设计文档 §2.2、§2.3；提案报告 附表 E）。该原则与国际通行的机器人排除协议（robots.txt）确立的采集伦理一致：网站方可声明自动化访问边界，采集方应予遵守（来源：IETF，2022）。

## 4.5 技术路线：三期推进

- **一期（M1–M2，第 1–6 月）文本闭环**：三张注册表与能力框架落地，五项核心能力上线，灵感简报与构思文档可用；优秀项目档案由 50 个扩至 200 个，白名单地区由 5 个扩至 10–15 个并上线晋升机制；试点组 5–10 名设计师真实使用；产出方法论论文 1 篇、软件著作权 1–2 项（出处：设计文档 §6；提案报告 附表 F）。
- **二期（M3，第 7–12 月）多模态升级**：部署 CLIP 类模型生成图像 embedding（来源：Radford 等，2021），实现“文脉找图”“相似风貌项目”图文混合检索；提案升格上线，形成内部构思与对外提案双形态产出闭环；产出论文、软著第二批（出处：设计文档 §6）。
- **三期（M4，第 13–18/24 月）生图集成与全院发布**：gen_image 对接公司生图服务；灵感助手切换正式可见性，全院发布；资产终盘目标为优秀项目档案 ≥300 个、地区档案 ≥20 个；完成 2–3 个真实项目效益回访，形成结题材料包（出处：设计文档 §6；提案报告 §4.5）。
