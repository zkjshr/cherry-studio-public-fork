# 第三章 技术现状

## 3.1 院内已具备的平台基础

我院已形成覆盖"前端交互—能力服务—知识存储—数据供给—算力支撑"的完整技术底座，五大核心组件均生产运行（现状依据：课题提案 §三 3.1）：

| 组件 | 现状 | 与本课题的关系 |
|---|---|---|
| 百事通桌面端 | 基于 Cherry Studio 企业化定制，助手/人格机制、插件市场、对话 UI 均已上线 | 零改动复用为前端，灵感助手以官方助手形式分发 |
| gateway 服务网关 | Python 服务网关，已具备知识检索（kb_search）、WeKnora 代理、企业用户鉴权、插件市场分发、模型代理等模块 | 课题新增能力的宿主，三层注册机制在此落地 |
| WeKnora 知识库 | 生产运行中，支持文档入库、分块、向量检索、混合检索 | 知识存储与检索引擎，不改造，仅新增两个知识库 |
| EKP 数据管道 | 生产运行中，持续自动化入库内部规范、图档、维基文档，已完成 1.1 万+ 文档入库 | 建档管道的数据源与工程范式参考 |
| 算力资源 | 两台 4090 GPU 服务，分别承担 LLM 推理与向量化 | 中期扩容多模态 embedding 的硬件基础 |

百事通已确立"能力即服务、知识即服务"的产品方向：智能体运行时保持通用，场景应用通过"人设 × 能力 × 知识"的组合配置（preset）快速生成（课题提案 §一 1.3）。架构约束为——桌面端零改动或极小改动，新逻辑全部落在 gateway，WeKnora 不改造（设计文档 §1 分层架构）。我院虽已通过 EKP 实现文档电子化归档与持续自动化入库，但知识资产以事务性内容为主，面向设计创作的知识（优秀项目设计要点、地域文化档案）尚未结构化沉淀（课题提案 §一 1.2）。平台能力与知识内容的这一落差，正是本课题的切入点。

## 3.2 行业技术现状

**（一）检索增强生成（RAG）技术已趋成熟。** RAG 由 Meta AI 等机构于 2020 年提出，将非参数化检索向量库与大模型生成相耦合，显著提升知识密集型任务的事实准确性，原始论文已被引用逾 3 万次（来源：Lewis et al.，NeurIPS 2020）。Gartner 预测，到 2028 年 80% 的生成式 AI 商业应用将构建于企业既有数据管理平台之上（来源：Gartner，2025），"企业自有数据 + 检索增强"已成为大模型企业级落地的主流路线；我院 gateway 与 WeKnora 的组合正是该路线的既有工程实现。

**（二）多模态检索技术进入可用阶段。** OpenAI 2021 年发布的 CLIP 模型以对比学习将图文映射至统一向量空间，实现零样本图文匹配，已成为图文检索的基础模型（来源：Radford et al.，ICML 2021）。本课题二期"文脉找图、相似风貌项目"检索即基于此类模型部署，属成熟技术的场景化应用。

**（三）建筑设计行业 AI 应用已现头部实践，但集中于创意表现环节。** 中南建筑设计院自 2022 年 3 月起研发 GIANT AI 平台并于年底全面投入使用，全院近百位设计师参与测试，累计生成效果图方案约 2400 个（来源：湖北日报，2024）。行业实践证明设计院具备 AI 工程化能力，但公开案例多聚焦效果图生成环节，面向"项目经验复用 + 地域知识调用"的前期策划场景尚无系统化落地报道（待核实）。

## 3.3 行业差距与本课题差异化定位

对照上述现状，现有技术方案存在三类共性差距：其一，通用大模型助手缺乏企业独家项目知识与结构化地域文脉数据，生成内容泛化不可信；其二，行业知识库产品以文档管理为主，仅支持原始文档检索，无面向设计场景的知识重组与生成能力，知识"存而不用"；其三，学术界文脉研究数字化多为单点研究（某地某要素），缺乏面向设计实务的持续更新数据服务。

本课题差异化定位为三重叠加：**独家内部项目经验（外部不可获取）× 结构化地域文脉库（行业稀缺）× 伴随式场景应用（超越检索问答）**（课题提案 §三 3.2）。就可行性而言，本课题待补齐环节——设计知识结构化、外部数据合规采集、多模态检索、生图集成——均为成熟技术的场景化集成，无不可控技术风险（课题提案 §三 3.3）。
