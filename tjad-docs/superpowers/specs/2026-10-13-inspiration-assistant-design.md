# 灵感助手（揭榜挂帅课题）设计文档

- 日期：2026-10-13
- 状态：设计定稿待评审
- 范围：全部在现有百事通架构内实现（Cherry Studio 桌面端 + gateway + WeKnora）

## 0. 背景与课题定位

揭榜挂帅课题若仅以"项目资料库"申报存在两大局限：交付物作为数据库无法直接赋能集团主业；定位偏技术驱动，未落到具体应用场景。

本设计将资料库课题升维为：**以"能力即服务、知识即服务"为方法论主轴，百事通为智能前端，场景应用（灵感助手）+ 数据资产（优秀项目库、地域文脉库）为交付物**的课题方案。

### 课题本质（方法论主轴）

百事通不做端到端写死的应用，而是：**智能体运行时 + 能力服务 + 知识服务；场景应用 = 人设 × 能力 × 知识的一份组合配置（preset）**。灵感助手是首个官方组合，用它证明方法论可复制。

### 交付物

1. **场景应用**：灵感助手——伴随式设计伙伴。
2. **数据资产**：优秀项目库（内部独家）、地域文脉库（外部采集）。
3. **方法论**：能力/知识/组合三层注册机制 + 知识资产沉淀机制（可复制到其他场景）。

### 验收口径

- 基本盘：A 使用数据（活跃用户、对话轮次、产出文档数）+ B 资产规模（档案数量、数据源清单、质量抽检）。
- 配齐：C 知识产权（论文、软著、方法论文档，专利视院要求）。
- 亮点（不强求）：D 效益案例（试点项目真实受益）。

## 1. 分层架构

```
┌─────────────────────────────────────────────────┐
│  Cherry Studio 桌面端（百事通）                    │
│  对话 UI · 助手/人格 · 插件市场客户端               │
└───────────────┬─────────────────────────────────┘
                │ X-Client-Token
┌───────────────▼─────────────────────────────────┐
│  gateway（能力服务层）                             │
│  ① 能力注册表：知识检索 / 地域检索 / 爬虫补充检索      │
│     生图服务适配 / 半自动建档 / 要素解析              │
│  ② 知识注册表：WeKnora 各知识库 → 标准知识服务        │
│     （优秀项目库 · 地域文脉库 · 规范库 …）           │
│  ③ 场景组合层：官方组合 preset（灵感助手 =           │
│     人格 + 能力集合 + 知识集合），后续可加编辑器      │
│  ④ 市场分发：能力/人格/组合 → 插件市场货架           │
└───────┬──────────────────────┬──────────────────┘
        │                      │
┌───────▼────────┐   ┌─────────▼─────────────┐
│ WeKnora 知识库  │   │ 外部能力               │
│ 优秀项目库      │   │ 爬虫/检索服务（新增）    │
│ 地域文脉库      │   │ 公司生图服务（适配接入）  │
│ 规范库（既有）   │   │ LLM（多模态，B 阶段）    │
└────────────────┘   └───────────────────────┘
```

设计要点：

1. **Cherry Studio 端零改动或极小改动**——灵感助手对用户就是一个官方助手；多模态图片展示复用现有对话渲染。
2. **新逻辑全部落在 gateway**：能力模块 + 建档工作流 + 三张注册表（SQLite，与 enterprise 库同范式）。
3. **WeKnora 仍是知识存储与向量检索引擎**，不改造；优秀项目库、地域文脉库是其中的新知识库。
4. **外部爬虫是独立服务**，gateway 通过它做补充检索并写回地域库，与 WeKnora 的 SSRF 白名单机制兼容。
5. **能力市场/人格市场**：不新造分发系统。能力在 gateway 注册后以插件/技能包形式上架现有插件市场（manifest 扩展 `capabilities[]`、`presets[]` 组件类型）；人格走现有 assistants 机制。

## 2. 数据资产设计

### 2.1 优秀项目库（内部独家资产）

项目档案数据模型（入库 WeKnora，元数据字段即检索维度）：

```
项目档案 {
  basic:    项目名 / 类型（公建·居住·更新·景观…）/ 地点（省·市·区）/
            规模 / 年代 / 状态（建成·在建·方案）
  design:   设计要点（200字内，LLM 提炼）/ 概念关键词 / 空间策略标签
  culture:  涉及的地域文脉标签（关联地域档案）
  honor:    获奖 / 发表 / 业主评价
  media:    图集（实景·效果图·图纸），B 阶段生成图像 embedding
  source:   EKP 原始文档 ID（可溯源）
}
```

**半自动建档工作流**（知识资产沉淀机制，方法论亮点）：

- EKP 原始图档/评优材料 → LLM 抽取草稿档案（结构化字段 + 图集归类）
- 质量分档：高置信自动入库 / 低置信进人工审核队列（对话式确认，不强求）
- 入 WeKnora 优秀项目库；抽取复用现有 qwen 模型管线经验
- **不复用现有 WeKnora 原始文档**（多为内部事务性内容），全部重新结构化整理

### 2.2 地域文脉库（外部资产）

双层结构：

- **白名单重点地区**（首批 10–20 个：长三角核心 + 业务重点城市）：完整本地档案，季度自动重爬刷新。
- **按需补充**：任务书涉及非白名单地区时实时爬取 → 轻档案（结构化摘要 + 来源链接）→ 高频命中地区自动晋升白名单（晋升机制本身是课题创新点）。

**数据获取原则**：引用优于拷贝——存"结构化摘要 + 来源链接"，仅白名单地区存全文/图集；只爬公开内容，不碰登录/付费墙。

地域档案数据模型：

```
地域档案 {
  geo:      行政区划码 / 名称 / 层级（省·市·县）
  history:  历史沿革（时间线）/ 城市演变 / 文脉叙事线
  culture:  文化要素（非遗·特产·民俗·地名典故，各带来源链接）
  fabric:   建成环境特征（格局·街巷尺度·材料·色彩·典型风貌元素）
  media:    风貌图集（B 阶段图像 embedding）
  meta:     来源清单 / 最近更新时间 / 命中次数（晋升白名单依据）
}
```

### 2.3 数据源矩阵（首期候选，做成可注册的采集器清单）

| 类别 | 候选源 | 用途 |
|---|---|---|
| 官方公开 | 政府文旅/规划网站、地方志数字化平台、文保名录 | 历史沿革、风貌、文保要素 |
| 百科知识 | 维基/百度百科（引用链接） | 快速背景补充 |
| 学术 | 公开论文摘要（知网只引题录不碰付费内容） | 深度文脉研究线索 |
| UGC/生活 | 马蜂窝、小红书公开页（摘要+链接） | 特产、当代生活气息 |
| 影像 | 公开图库/政府风貌图集 | 风貌图集（注意版权标注） |

每个数据源一个 adapter，声明覆盖范围/更新频率/合规级别——采集器本身也在能力注册框架内，方法论自洽。

## 3. 灵感助手工作流与能力编排

### 3.1 核心工作流（首期全文本）

```
① 任务书上传/粘贴
② 要素解析 parse_brief → 要素卡（功能/地点/规模/风格/约束）→ 用户确认
③ 检索编排（并行，按需触发）
   ├─ search_projects   WeKnora 优秀项目库（向量+元数据过滤）
   ├─ search_region     本地地域档案；未命中 → 触发补充检索
   └─ search_external   爬虫服务按需采集 → 轻档案 → 写回地域库
④ 灵感简报 synthesize_brief（项目解读·参考项目·文脉线索·设计切入方向，全部注明来源）
⑤ 伴随式对话（循环）：只重跑需要的环节，会话状态维护"要素卡 + 已采纳方向"
⑥ 沉淀 gen_concept_doc 《项目构思文档》（内部版），素材回链
⑦ 升格 upgrade_proposal 《前期策划提案》（对外版），文风切换由人格层完成
```

产出一体两面：内部构思（B）成熟后升格为对外提案（A），分阶段完成。

### 3.2 能力清单与接口契约

所有能力是 gateway 上的 HTTP 端点，LLM 以 tool/function 方式调用；输入输出由 JSON Schema 声明——**Schema 即"能力即服务"的接口契约，也是上架市场的清单**。

| 能力 | 输入 | 输出 | 依赖 |
|---|---|---|---|
| `parse_brief` 要素解析 | 任务书文本/文件 | 要素卡 JSON | LLM |
| `search_projects` 项目检索 | 要素卡/自由文本 | 项目档案卡[] | WeKnora |
| `search_region` 地域检索 | 地点名/要素卡 | 地域档案或"未建库"标记 | WeKnora |
| `search_external` 外部补充 | 检索意图 | 轻档案[]（含来源） | 爬虫服务 |
| `synthesize_brief` 简报生成 | 要素卡+检索结果 | 简报结构 | LLM |
| `gen_concept_doc` 构思文档 | 会话状态 | Markdown 文档 | LLM |
| `upgrade_proposal` 提案升格 | 构思文档+补充素材 | 提案框架 | LLM |
| `gen_image` 意向图（C 预留） | 文本/参考图 | 图片 | 公司生图服务 |
| `archive_project` 建档（后台） | EKP 文档 ID | 项目档案草稿 | LLM |
| `crawl_region` 地域采集（后台） | 地区+采集器 | 地域档案/轻档案 | 爬虫服务 |

关键设计点：

1. **会话记忆显式化**：结构化"任务状态"（要素卡+已采纳方向+已用素材），每轮更新；长对话不漂移，文档沉淀有可靠输入。
2. **检索编排是运行时组合**：三个检索并列注册，由 LLM 工具调用机制按需组合——与"场景=组合"方法论一致。
3. **A→B 不返工**：B 阶段仅检索返回变为"文本+图集"，图像 embedding 离线生成，对话链路不变。
4. **C 只加不改**：`gen_image` 注册即用。

## 4. 组合配置与市场分发

### 4.1 三张注册表（gateway SQLite，与 enterprise 库同范式）

**能力表 `capabilities`**：id / name / category（检索·生成·采集·建档·图像）/ endpoint / input_schema / output_schema / requires / modality / status(draft·published·deprecated)。

**知识表 `knowledge_sources`**：id / name / kind / kb_id（WeKnora 知识库 ID）/ metadata_fields / access(official·pilot·internal) / stats（docs·last_synced，资产规模指标自动统计）。

**组合表 `presets`**：id / name / persona（system_prompt·model·temperature）/ capabilities[] / knowledge[] / opening / visibility(official·pilot·draft)。

灵感助手 = 三行引用的集合；换一份 preset 即另一个场景（如"规范问答助手"）。结题时这是"可复制性"的直接证据。

### 4.2 市场衔接与权限

- preset 下发自动生成官方助手条目，走现有 assistants 分发。
- 上架复用插件市场范式（gateway 目录即货架，scp 上架，无管理端写接口），manifest 扩展 `capabilities[]`、`presets[]` 组件类型。
- 权限：试点期 `visibility: pilot` + 试点组名单（复用 enterprise 用户/token 机制）；验收时切 `official` 即全院发布。

### 4.3 运行时拼装（一条消息的生命周期）

客户端带 assistant id 调 gateway /chat（现有链路）→ 查 presets 取组合 → capabilities 注入本轮 tool 列表 → knowledge 决定 kb_search 允许范围 → persona 组装上下文 → LLM 按需调用能力端点 → 流式返回。客户端感知只是"一个功能很多的助手"，端上零架构改动。

## 5. 输出三级阶梯

| 级别 | 内容 | 依赖能力 | 可用时点 |
|---|---|---|---|
| **L1 检索原始结果** | 三路检索原文素材包：项目档案列表、地域档案原文、外部来源链接，带引用未加工 | `search_*` 三件套 | M1 |
| **L2 生成报告** | 灵感简报/构思文档：LLM 融合加工，结构化有叙事线，素材全回链 | + `synthesize_brief` / `gen_concept_doc` | M1–M2 |
| **L3 图文+效果图** | L2 基础上附图集 + 生图服务产出的意向效果图 | + 多模态检索 + `gen_image` | M3–M4 |

设计决定：

1. **阶梯是能力自然涌现的，不是三档写死的功能**。用户正常提需求，助手按当前已注册能力尽力给到最高级，能力未上线自然降级——阶梯同时就是阶段路线图。
2. **L1 素材包是标准可复制产物**：结构化 JSON + 来源清单，既是用户兜底结果，也是 L2/L3 的输入、建档管道的中间件，一次实现三处复用。
3. **效果图严格标注"AI 意向图"**（元数据 `provenance: generated`），与项目库实景图区分，避免误当真实案例参考。

## 6. 里程碑计划与验收映射

### M1（第 1–3 月）：文本闭环跑通（A 里程碑）

- 架构：三张注册表 + 能力框架落地 gateway，preset 机制上线
- 能力：parse_brief / search_projects / search_region / search_external / synthesize_brief（全文本）
- 数据：优秀项目库首批 **50 个档案**；地域库首批 **5 个白名单地区**（长三角）；爬虫 MVP（2–3 个 adapter）
- 应用：灵感助手 preset 上架，试点组 5–10 名设计师真实使用
- 演示：真实任务书 → 灵感简报 → 追问深化（中期检查材料）

### M2（第 4–6 月）：伴随体验 + 建档规模化

- gen_concept_doc + 来源回链上线，会话状态机制成熟
- 项目库扩至 **200 个**；白名单地区 **10–15 个**，季度重爬 + 晋升机制上线
- 对话式人工审核队列上线，建档吞吐可统计
- 知识产权第一批：方法论文案 1 篇 + 软著 1–2 项

### M3（第 7–12 月）：多模态升级（B 课题目标）

- 建档/采集管道加图像 embedding（CLIP 类模型部署至新 4090）
- 检索返回图文混合；"文脉找图""相似风貌项目"可用
- upgrade_proposal 上线，A/B 双形态产出闭环
- 论文/软著第二批；使用数据报表（已积累半年+）

### M4（第 13–18/24 月）：生图接入 + 全院发布 + 结题

- gen_image 接公司生图服务（C 阶段）
- visibility 切 official 全院发布（验收演示环节）
- 资产终盘：项目档案 ≥ 300–400、地区档案 ≥ 20、外部来源清单完整
- 效益案例回访 2–3 个真实项目；结题材料包（演示+资产清单+使用数据+论文/专利/软著+方法论文档，含"可视化组合编辑器"二期展望）

### 验收映射

| 验收项 | 支撑 | 阶段 |
|---|---|---|
| A 使用数据 | gateway 使用统计 + 试点→全院轨迹 | M1 起，M3 报表 |
| B 资产规模 | 两库档案数 + 数据源清单 + 质量抽检 | M1–M4 滚动 |
| C 知识产权 | 论文 2 + 软著 3–4 + 方法论文档 | M2、M3 |
| D 效益案例 | 试点项目回访 | M4 |

## 7. 风险预案

1. 外部数据源质量参差 → adapter 合规分级 + 白名单人工抽检
2. LLM 抽取质量不足 → 质量分档阈值可调 + 人工队列兜底
3. 多模态算力不足 → 与现有 Ollama 服务同机评估；不可行则降级为"图集展示无 embedding"，检索以元数据过滤为主，不阻塞 B 验收
4. 生图服务对接受制于对方排期 → C 阶段本为预留，可后移
